# Nura — Final Functional Polish: Settings, Feedback, Save & Delete Actions

Keep the existing Nura design, layout, colors, navigation, and mobile-first iPhone experience.

Do not redesign the product.

This is a **functional polish and feedback pass**.

The application currently has several actions that work partially but do not clearly tell the user what happened.

For every important action, the user must receive clear confirmation and the data/state must actually be updated.

# 15. REMINDER STATUS SUMMARY

Use exactly these statuses:

### Upcoming

The date has not arrived.

### Due

The date has arrived but the user has not completed the reminder.

### Rescheduled

The user moved the reminder to a new date.

### Completed

The user confirmed they went and saved the visit.

### Missed

The user explicitly marked the reminder as missed.

Never show a reminder as Completed unless the user actually completes the "I went" flow.

# FINAL PRINCIPLE

Every important user action in Nura should answer one simple question:

**"Did Nura actually do what I asked?"**

The interface should make that obvious.

Save → Saved

Submit → Sent

Reschedule → Rescheduled

Keep for later → Due

Miss → Missed

Complete → Completed

Delete → Deleted

Add family member → Added

This should be reflected both in the UI **and in the underlying application state/data**.
