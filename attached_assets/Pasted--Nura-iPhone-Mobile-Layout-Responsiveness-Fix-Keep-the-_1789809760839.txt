# Nura — iPhone Mobile Layout & Responsiveness Fix

Keep the **existing Nura visual design system exactly as it is** — soft sky blue, white cards, dark navy typography, blue primary actions, rounded cards, calm healthcare aesthetic.

Do NOT redesign the product from scratch.

The current screens look good visually, but they are behaving like fixed-size desktop/web compositions placed inside an iPhone frame. Convert the entire prototype into a **true mobile-first iOS application layout**.

## 1. Primary requirement

Nura must be designed as a real **Apple iPhone mobile application**, not a web page or desktop dashboard.

Every screen must:

* Fit completely inside the iPhone viewport.
* Respect the Dynamic Island / top safe area.
* Respect the bottom Home Indicator safe area.
* Never allow text, buttons, cards, icons, or navigation to be clipped.
* Never depend on a fixed screen height.
* Never position important content based on absolute coordinates.
* Adapt vertically when content becomes longer.
* Allow the user to scroll naturally.
* Keep the bottom tab bar fixed within the iOS safe area.
* Work on both smaller and larger iPhone screen sizes.

Use responsive/adaptive layout principles rather than scaling the entire screen as one image.

Apple's guidance is to keep foreground interactive content within safe areas and use adaptive layouts rather than assuming a particular screen size.

---

# 2. Target devices

Optimize the prototype for modern iPhones including:

* iPhone SE / smaller viewport
* iPhone 15 / 16
* iPhone 15 Pro / 16 Pro
* iPhone 15 Pro Max / 16 Pro Max

The UI must remain usable across different heights and widths.

Do not create separate designs that simply stretch or shrink.

Use responsive constraints, flexible vertical stacks, intrinsic content height, and scrollable content.

---

# 3. Safe-area requirements

Create a proper iOS safe-area structure.

### Top

Do not place:

* NURA logo
* page title
* profile icon
* buttons
* cards
* text

under the Dynamic Island.

Maintain appropriate top spacing automatically.

### Bottom

The bottom navigation must sit above the iPhone Home Indicator.

Content must never disappear behind the tab bar.

The final card/item on every scrolling screen must have enough bottom padding so the user can see and interact with it.

# 17. Typography

Do not allow typography to cause clipping.

Use:

* responsive text containers
* natural text wrapping
* intrinsic height
* appropriate line spacing
* maximum readable line lengths

Never force text into a fixed-height card.

If text becomes longer, the card becomes taller.

---

# 18. Cards

Cards must use:

Auto height

Not fixed height.

Content should determine the card height.

For example:

Short content → short card

Long notes → taller card

Multiple medications → taller card

Multiple tests → taller card

Never cut text with hard clipping.

If content is intentionally collapsed, use:

View more

instead of cutting content.

---

# 20. Mobile interaction

All primary actions must be comfortable for touch.

Buttons should have sufficient touch area.

Avoid tiny text links or tiny icon-only controls for important actions.

Use familiar iOS interaction patterns where appropriate:

* sheets
* cards
* navigation stacks
* confirmation dialogs
* segmented controls
* bottom sheets

Keep the interface calm and simple.

---

# 21. Do NOT change

Do not change:

* Nura branding
* "Your family's health, remembered."
* current blue/white color system
* current typography style
* current card style
* current overall visual personality
* current navigation concept
* overall calm healthcare aesthetic

The goal is to **fix the mobile implementation, not redesign the product.**

---

# 22. Critical prototype QA

Before considering the prototype complete, test every screen at multiple iPhone viewport sizes.

Check:

1. Is anything hidden behind the Dynamic Island?
2. Is anything hidden behind the Home Indicator?
3. Is any text clipped?
4. Are buttons fully visible?
5. Are cards allowed to grow vertically?
6. Can the user scroll to every piece of information?
7. Does the bottom navigation remain accessible?
8. Does the last item have sufficient bottom spacing?
9. Does long medication information fit?
10. Does the reminder completion flow work?
11. Does completed reminder information enter History?
12. Can additional family members be added?
13. Does Feedback submit successfully?
14. Does Logout exist?
15. Are there any desktop/web-style fixed-width layouts?

### Final requirement

Nura should look and behave like a **real native iPhone health app**, not a website placed inside an iPhone mockup.

Prioritize **responsive layout + safe areas + scrolling + complete information visibility** over fitting more content onto a single screen.

No important information should ever be cut just to make a screen look visually compact.
